# go-envelopes v0.5.0

This release makes the core manifest assert wire identity only, adds typed
response channels and explicit host type-support declarations, and introduces
the independent admin contract with its optional HTTP binding. Source range:
`v0.4.0..80820fbaff26d6cf2bdd9d41b4a18d79c80226c9`.

## Highlights

- Core renderer locations, exports and prop conventions belong to hosts.
  The manifest, metaschema and `ManifestEntry` no longer carry `component`,
  `export` or `props`. Core-only `ENVELOPE_IMPORT_METADATA` is empty.
  [Source: f1593e4](https://github.com/hollis-labs/go-envelopes/commit/f1593e4e7a357dc728f17d5379e1e2d98e97d31e).
- `Response.Answers` and `.Decisions` are optional typed channels alongside
  `Payload`. `ResponseStatus.IsTerminal` distinguishes immutable terminal
  responses from replaceable partial drafts. The host owns conflict transport
  and persistence.
  [Source: 8827ce4](https://github.com/hollis-labs/go-envelopes/commit/8827ce41ec220719cb59732f35c35e12308dc327).
- `TypeSupport`, `CheckSupport` and `SupportedTypes` let a host account for
  supported types and named exclusions, without a library-imposed catalog
  partition or emission policy.
  [Source: 91d9ea3](https://github.com/hollis-labs/go-envelopes/commit/91d9ea34e2b214cc99fc7d3fb4ebd5a3305b7ad5).
- `admin` provides app-scoped declarations, flat scalar and semantic settings
  validation, redacted snapshots, observations and host adapter contracts.
  `admin/adminhttp` supplies a host-mounted handler with explicit authorization,
  command protection, strict decoding, ETags and staged transaction orchestration.
  Storage, atomic durability, live application and lifecycle remain host-owned.
  [Sources: 1fabfa3 / PR #4](https://github.com/hollis-labs/go-envelopes/commit/1fabfa3a783cacf326359ea38eb1a9efe412839a),
  [59c1506 / PR #5](https://github.com/hollis-labs/go-envelopes/commit/59c150641cfab728f74621098c506279652d84e2).
- The module requires Go `1.26.6`, raised from `1.26.1`.
  [Source: e507597](https://github.com/hollis-labs/go-envelopes/commit/e5075970a913bf3f50692bc0444053e3a90566ca).

## Migration from v0.4.0

### Manifest and Go source compatibility

This is a breaking minor release under the module's pre-1.0 policy.
Code reading `ManifestEntry.Component`, `.Export` or `.Props` no longer compiles.
Remove those reads and own the binding table in the host. The manifest
metaschema rejects those keys; decoding preserves unknown keys in `Extra`
rather than silently stripping them. `ImportMetadata`,
`TypeSpec.TypeScript.Import`, `TypeSpec.UIMetadata` and plugin-facing `ui:`
metadata remain; only core component hints become empty.
[Source: f1593e4](https://github.com/hollis-labs/go-envelopes/commit/f1593e4e7a357dc728f17d5379e1e2d98e97d31e).

The deleted schema resources are `giphy-modal.schema.json`,
`kb-result.schema.json`, `resolution-capture.schema.json`,
`ticket-confirmation.schema.json` and `ticket-form.schema.json`.
They lacked core manifest entries and were not registered by `LoadCore`.
Consumers resolving them through the exported catalog must stop relying on
them or supply their own schemas. The unregistered-schema API/flag remains;
it includes nothing additional for this core catalog.
[Source: f1593e4](https://github.com/hollis-labs/go-envelopes/commit/f1593e4e7a357dc728f17d5379e1e2d98e97d31e).

Prepared consumer migrations illustrate different host arrangements:

- [Nanite #438](https://github.com/hollis-labs/nanite/pull/438) moves bindings to
  host-owned JSON with explicit renderer/backend-only dispositions. Its minimal
  generator guard deliberately couples catalog types to that table and names a
  type lacking a disposition, preventing silent loss of bindings on regeneration.
- [Tangent #76](https://github.com/hollis-labs/tangent/pull/76) already owns its
  real renderer bindings. It clears obsolete core component slugs from an unused
  informational map and proves the existing real-router fallback/cancel path.
  It does not add a guard to that informational map or invent renderer bindings.

These examples describe prepared PRs, not merged adoption or a requirement to
use either host's binding format. Review generated diffs and exercise the real
rendering path in the consuming application.

### Responses and reflected JSON schemas

Answers carry `questionId`, `value`, optional `acceptedSuggestion` and `note`;
decisions carry `itemId`, `action`, optional `note` and `meta`.
`acceptedSuggestion` is a pointer, distinguishing false from absence;
decision action is an open string. `ValidateResponse` rejects empty question
IDs, item IDs and decision actions for every response kind.
Both channels use `omitempty`: nil or empty channels preserve legacy
payload-only JSON. Nonempty channels add fields intentionally.
[Source: 8827ce4](https://github.com/hollis-labs/go-envelopes/commit/8827ce41ec220719cb59732f35c35e12308dc327).

Reflection of `Response` can nevertheless change an advertised public schema.
Tangent's actual MCP session fixture adds these properties under the
`tangent.session_get` output's `envelopes_history[].response`:

| Property | Before | After |
| --- | --- | --- |
| `answers` | Absent | Optional null-or-array. Item requires `questionId:string`, `value:any`; optional `acceptedSuggestion:null-or-boolean`, `note:string`; item additionalProperties:false. |
| `decisions` | Absent | Optional null-or-array. Item requires `itemId:string`, `action:string`; optional `note:string`, `meta:object` (additionalProperties:true); item additionalProperties:false. |

Existing properties, types and required lists are unchanged. The fixture found
no input-schema changes or other advertised output-schema changes; its legacy
payload bytes remained identical. The cause is `8827ce4`, not the support API
commit. This is evidence for that fixture, not arbitrary consumers or installed
plugin tools. Tangent's freeze requires a separately accepted ADR before a
digest refresh; its migration prepares proposed ADR0011 and the refresh in
separate commits. Tangent-inbox has byte-identical relevant reflection/freeze
source, so the same exposure is inferred on adoption; inventory only was done.
[Source: Tangent #76, including the complete field diff](https://github.com/hollis-labs/tangent/pull/76).

Terminal statuses are `submitted`, `canceled`, `error` and normalized legacy
`cancelled`. `partial` and unknown statuses are not terminal. The documented
host contract rejects a later submission against a terminal response as a
conflict carrying the recorded response; a later submission replaces a partial
draft. This library does not install a response endpoint or storage adapter.
[Source: 8827ce4](https://github.com/hollis-labs/go-envelopes/commit/8827ce41ec220719cb59732f35c35e12308dc327).

## Admin command ordering

PR #6 checks declaration revision before group keys/types and current effective
permissions, then ETag, after authorization/protection and structural decoding.
Stale declaration revision plus an unknown group key now returns 409
`manifest_changed`; the unknown key with current revision returns 400.
When both revision and ETag are stale, 409 wins. A stale ETag with current
revision remains 412 `value_conflict`. This applies to validate and transactional
update/reset; malformed bodies still fail before revision checking.
[Source: 83386cd / PR #6](https://github.com/hollis-labs/go-envelopes/commit/83386cd78c2ac5a1f5dbcf91508951b10cd3611e).

Update/reset require a concrete strong If-Match ETag; missing precondition is
428. Mutation validation failure is 422, while completed validate returns 200
with valid/invalid results. Read/Preview base inconsistency returns sanitized
503 `backend_unavailable`, not completed validation. Hosts supply transaction
durability and version invalidation across every enabled layer. No automatic
retry or restart is supplied.
[Source: 59c1506 / PR #5](https://github.com/hollis-labs/go-envelopes/commit/59c150641cfab728f74621098c506279652d84e2),
[race regression coverage, 51e60dd](https://github.com/hollis-labs/go-envelopes/commit/51e60ddb01b2b3ff01bb8278e60397c96fd77cce).

## Cancellation compatibility retained

`cancelled` / `user-cancelled` compatibility and deprecated Go constants are
retained in v0.5.x. Removal is not scheduled and will be announced first.
New output remains `canceled` / `user-canceled`; use
`ResponseStatus.Canonical` and `CanonicalErrorCode` before re-emitting stored
legacy values. This supersedes the removal schedule in the published v0.4.0
release notes, which remain historical.
[Source: b6ec75d / PR #7](https://github.com/hollis-labs/go-envelopes/commit/b6ec75d8211c56757699ed5fe645b4eb318510e7).

PR #7 changes the session-task status description, not its enum or validation.
That metadata correction changes catalog identity and generated documentation;
regenerate consumers when repinning. Module version, `Envelope.V` and
`admin.ContractVersion` remain independent; `ProtocolVersion` remains 1.
[Sources: b6ec75d](https://github.com/hollis-labs/go-envelopes/commit/b6ec75d8211c56757699ed5fe645b4eb318510e7),
[wire types at reviewed main](https://github.com/hollis-labs/go-envelopes/blob/80820fbaff26d6cf2bdd9d41b4a18d79c80226c9/types.go).

## Generator upgrade

Once v0.5.0 is tagged, pin it in the consumer module, then regenerate from that
module's selected dependency:

```sh
go get github.com/hollis-labs/go-envelopes@v0.5.0
go run github.com/hollis-labs/go-envelopes/cmd/envelopes-export \
  -format typescript -output envelope-types.generated.ts
```

Catalog wrapper generators can use `-format catalog` instead. See the
[changelog](../../CHANGELOG.md), [generation guide](../generation.md),
[admin contract](../../admin/README.md) and
[HTTP binding](../../admin/adminhttp/README.md) for the complete surfaces.
